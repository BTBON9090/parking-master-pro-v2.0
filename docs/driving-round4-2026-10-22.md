# 第四轮：驾驶连续性、轮组、座舱、阴影与六车道

日期：2026-10-22  
范围：P0 转向/顿挫、P1 轮胎/座舱/阴影/主干道标线。没有重建关卡，没有修改外部车型资产文件，没有恢复菜单音乐。官方规范只作为标线语义参考，不声称本游戏尺寸/图形是法定认证。

## 1. 根因与处理

### 1.1 方向盘方向与过敏

- **已确认符号链**：输入角为正 = 右转；`advanceVehicleCenter` 的正曲率、前轮 `rotation.y = -ackermann`、CSS 轮盘正角（顺时针）一致。问题在驾驶员视角的三维轮盘：司机朝 +Z 看，正 Z 旋转在屏幕上呈顺时针；旧代码用 `rotation.z = -deg`，所以打右时轮盘反而逆时针。现改为单一 helper `driverWheelRotationZ(deg)`，只取正号，不再复制符号逻辑。
- **输入过敏**：鼠标每像素 2.5° 改为 1.7°；曲线总体灵敏度 0.65→0.58；键盘从“按下即固定 10°/帧”改为 9°/帧的 0.9 s 渐进斜坡（短按约 30% 起始幅度）；速度回压每 tick 2.5°→1.2°；自动回正刷新 16→33 ms，并保留低速满舵。
- **高速限制**：速度因子从 25–140 km/h 的 0.82 强度改为 30–160 km/h 的 0.76 强度，过渡更缓；120 km/h 仍有约 0.42 的可用锁角，不再突然夹死。
- 新增测试：正/负曲率方向、司机轮盘正角符号、方向盘角度单位、低速/高速锁角差。

### 1.2 前进行驶顿挫

**先记录事实**：你实测巡航速度跃变为 0.000 u，单帧位移 2.40–2.90 u，说明没有“瞬时停走式速度跳变”。问题更可能是帧时间波动/渲染开销，而不是纵向速度函数本身。

已确认的高频来源并修复：

1. `UIOverlay` 的转速平滑 effect 以 16 ms 运行，依赖数组包含 `visualRpm`，每次 setState 都销毁/重建 interval，并让整个 HUD（含镜框、SVG 路线图）每秒重渲染约 60 次。现改为 ref 驱动、50 ms（20 Hz）、稳定 effect；稳定时抑制无变化 setState。
2. 路线地图 pose 更新从 12.5 Hz 降到约 8 Hz；整张静态 SVG 用 `useMemo` 固化，marker 单独更新，不再随每个物理读数重建所有道路/建筑节点。
3. 物理调试读数在 UIOverlay 内限制到约 15 Hz；调参面板仍保留约 30 Hz 的独立读数。HUD 不再每个物理 tick 往返 React。
4. 相机 FOLLOW/斜视的固定 `.lerp(0.16/0.22)`、`smoothPolar += .15` 改为按 `frameScale` 的指数系数；悬挂车身高度/俯仰/侧倾、道路俯仰、非悬挂弹簧和腾空速度改为时间缩放/子步，避免 30/60/120 Hz 下同一参数不同速度。
5. Cannon 顺序改为“先用上一帧刚体速度 step，再写本帧运动学”。旧顺序先把主车写到当前位姿再 step，刚体会比主车多前进一帧、下一帧被拉回，锥桶/交通接触时形成位置双写。
6. 主车 mesh 只有一处 `position/rotation` 写入；镜面/俯瞰是独立 pass，未写回主车。

这些是**已确认的代码/架构问题**；“相机固定系数”与“Cannon 顺序”对特定顿挫的贡献仍需实机对比，不能单独当作已证根因。测得的帧时是窗口采样，不是全程 60 fps 证明。

### 1.3 轮胎椭圆、低模与轮组绑定

- 旧 GLB 的整车按 width/height/length 三轴非均匀缩放；原轮胎几何在把轮组提升到车体根节点时把三轴缩放烘进了轮面，因此正侧视也会竖长/椭圆。
- **没有**把整车改成等比缩放：车体仍按 `cc.width/height/length` 归一化，碰撞 footprint、轮距、座位/镜面/驾驶眼位继续用原 cfg。
- 轮组改为在车体根节点下重建：每个车轮取原轮位的世界包围盒，生成共享的 **36 周向 × 12 管向圆环胎体 + 开口金属轮辋 + 5 辐 + 轮辋唇 + 轮毂**。轮辋筒 `openEnded=true`，不再用实心圆柱端盖遮住轮辐。轮胎轴为局部 X，滚动仍由既有 `rollPivot.rotation.x` 驱动，转向仍由 `steerPivot.rotation.y` 驱动。几何/材质共享。
- 圆胎半径改用源轮**垂直半径** `worldSize.y/2`，而不是 max(y,z)；若源轮心低于新半径，轮心抬到半径高度，避免把胎底沉进路面。
- 7 车实测/自动断言：车体宽 19.2–21.7、长 45.5–55.1、车顶高与 cfg 差 <1%，四轮世界径向 y/z 差 <4%。碰撞仍按 cfg；没有“轮胎圆了但车变窄”。
- NPC/交通车、主车和**静止停放车**现在共用同一圆胎几何/材质。停放车模板构建时先排除原 GLB 的 wheel/tyre/tire 网格，再按每个模型/楼层生成 5 个静态 `InstancedMesh`（胎体、开口轮辋、5 辐、轮辋唇、轮毂），每个车位 4 个轮矩阵一次写入；不增加每帧更新，不修改原 GLB 文件。可见车轮位置由车位宽/长包络近似（横向 0.38w、纵向 0.30l、半径 0.16min(w,l)），避免依赖部分资产不可拆分的整轴轮网格。
- **技术约束/回退**：如果某源资产既没有可识别的 wheel/tyre/tire 节点，也没有相应网格名，原轮网格无法安全地从车身中剔除，会保留原轮并叠加圆胎；当前北京停放车所用资产可被提取或按名称过滤。没有为此改原 GLB 或引入每车逐帧逻辑。

### 1.4 第一人称座舱

- 旧第一人称只隐藏 `playerBodyMeshes`，没有隐藏独立 `wheelMounts`，所以前轮成为两块黑凸起。现已隐藏完整轮组，镜面/俯瞰/外部 pass 恢复；新增 A 柱端点回归。
- A 柱改为**两个显式 3D 端点之间的梁**：下端 `(±0.47w, .30h, .14l)`，上端 `(±0.47w, 1.10h, .22l)`；顶棚横梁端点严格使用同一 `x/y/z`，横梁左右端 = 两根柱顶。新增 `roof-panel` 从横梁向后延伸，形成薄顶棚边缘，而不是悬空横条。测试直接断言柱顶 Y/Z 与横梁端点相等。
- 新增低多边形引擎盖、翼子板棱线、风挡下沿；位于内饰 group，仅第一人称可见，镜面/外部不出现浮空座舱。
- 仪表仍在下方 1/3，左右镜之间；1153 px 时镜间 gap 459.3、仪表 329.2；<1450 px 训练提示默认折叠为按钮。

### 1.5 阴影

- 太阳阴影默认开启：近范围正交视锥 ±220、1024²、PCF、`radius=1.5`；主车/近处 NPC/建筑投射，树冠/远景不额外增加 casters。
- 关键性能修复：`shadowMap.autoUpdate=false`，每个显示帧只在主渲染前 `needsUpdate=true` 一次；镜面/俯瞰复用同一 shadow map，避免每个 mirror pass 重跑全部阴影 caster。
- 接触阴影 texture 改为更紧的衰减，车辆/建筑 contact blob 缩小、降低不透明度；不再用大范围黑雾代替太阳阴影。
- 视觉差异与最终帧时未由本实现方截图证明。

### 1.6 六车道与标线

- 四条主干道统一 **210 世界单位 / 6 车道 / laneWidth 35**（双向各 3 车道，中央双黄）；胡同保持 60–80 的共享窄街，不画多车道。
- 旧标线按 24 单位块、每 3 块才画 `line-solid`，造成随机漏段/实线节奏错误。现按“无路口可见 run”生成：
  - 中央连续双黄（路口开口裁切）；
  - 两侧白色实线边线；
  - 同向车道白色虚线（长 run，`addMarking` 的 20/16 连续节奏）；
  - run 两端各 50 单位、路口前改为白色实线（禁止变道）；
  - 胡同口不画贯穿主路的多车道线。
- 四条主街路口臂统一 `lanes=3,width=210`；路口补片尺寸按最大臂宽生成。胡同口斑马线移到主路边缘外 125 单位，停止线 150，避免与主路边缘/车道线重叠。
- 上轮 S 弯 T 口修复保留：`markingGaps` 裁掉两条曲线路边线/箭头/道钉，三臂圆角补片仍存在。
- 主街建筑 31、车位/道路 SAT、路边车位不占车道、NPC/曲线路/S T 数据均有断言。新增主街宽度、3 车道臂、白色虚线/双黄/实线存在性断言。
- **标线颜色语义修复**：旧 `addMarking` 把非 rgba、非黄色的所有颜色都落到 `Mats.lineWhite()`，于是 `#2b2d31` 轮胎磨痕和 `#282a2e` 伸缩缝被画成白实线，混入中央黄线旁。现由 `markingMaterial(color)` 统一解析：白/黄复用缓存交通漆，其他明确颜色按颜色缓存为独立 Lambert 材质；合批 key 同时包含材质 uuid、实际色、透明度与 renderOrder，避免不同色误合并。新增回归断言暗色保留 hex、不同暗色不同材质/批 key、白黄不混。`docs/round4-road-stage.png` 记录修复前现象。
