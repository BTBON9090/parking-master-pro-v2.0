# 逐轮驱动与差速器：当前边界与实施清单

## 当前已经实现

- `utils/longitudinal.ts` 计算一个整车纵向速度与动力；`utils/powertrain.ts` 按前驱、后驱、四驱调整驱动轴静态载荷和纵向载荷转移后的整体牵引上限。不同动力布局已影响整车计算，但不是逐轮扭矩解算。
- `components/GameCanvas3D.tsx` 根据整车当前位置调用 `worldSurface` 或 `challengeGripAt`，将整车路面 / 天气附着力送入纵向和侧向模型。当前不是左右轮分别取样。
- 同一文件通过路径几何产生左右轮不同的**视觉滚动速度**；`utils/wheelSpin.ts` 给离地轮提供按驱动布局和油门变化的近似角速度。它们不反过来产生轮胎接触力。
- `utils/chassisSupport.ts` 的 `stepChassis` 能给各轮计算悬架支撑、接地间隙和载荷估算；接触数组沿 `rigWheels` 顺序。全车飞出时采用简化弹道，翻滚使用 `three/vehicleRollover.ts` 刚体。

## 正式游戏尚未实现

正式游戏没有逐轮角动量、轮轴扭矩、滑移率及其反作用力；没有可由低附着力轮限制同轴扭矩的开放式差速器，没有针对 AWD 明确建模中央差速器 / 分动箱；未模拟左轮在泥地、右轮在干地时的一轮空转与车辆实际受力。现有几何差速和空转动画不应称为物理差速器。碰撞翻滚时油门影响轮速画面，但并不驱动车辆刚体。

## 安全实施步骤

1. 在 `utils/chassisSupport.ts` 暴露各轮当前接地点、接地状态、估计垂直载荷，标注单位并验证三轮 / 四轮 / 多轴的索引和载荷总和。无效接触或飞行状态显式归零。
2. 在 `components/GameCanvas3D.tsx` 对各接地点按地图类型取样路面摩擦（参考 `utils/openWorld.ts` 的 `worldSurface`、`utils/challengeMaps.ts` 的 `challengeGripAt`），与天气统一计入一次；复用空间索引和上一固定步状态，避免每渲染帧多次昂贵查询。
3. 在固定时间步维护逐轮角速度、半径、惯量，计算轮胎纵向滑移率、驱动 / 制动扭矩及摩擦上限，并把接触反力汇总到 `utils/longitudinal.ts`。轮速用于动画、声音和滑痕，不再另造相互矛盾的表现。
4. FWD / RWD 选择对应驱动轴；同一轴开放式差速器以左右相同扭矩为基础，低附着一侧限制稳态传递，轮惯量应允许过渡。AWD 的前后扭矩分配 / 中央差速器与多轴轮组策略明确标为游戏标定，不以四驱直接推断更大马力。
5. 将悬架、轮胎力、车身纵向动力的先后顺序改为固定步耦合，限制时步与数值范围；处理换挡、发动机熄火、手刹、坡道、ABS、反向和飞行 / 翻滚切换。避免车轮瞬移、能量凭空增加、漂移或失去制动。
6. 在保留现有驾驶测试的基础上加入下面的定量回归，再以同设备同路线测试安卓性能与温升。需经过实驾才可以宣称达到验收；缺乏实车数据时不宣称厂家标定。

## 验收用例

- FWD / RWD / AWD 分别确认只有驱动轮受动力；空挡 / 熄火无驱动；自由轮在接地时由路面带动。
- 同轴左干右泥、左右互换、一个驱动轮离地、两轮离地；开放式差速器低附着侧滑移更大，牵引力受到限制。再覆盖左右均匀干 / 湿 / 雪路与低速坑洼。
- 测试多个后轴的重卡、单前轮三轮车、普通四轮车，不假设始终四个轮。履带车辆维持独立双侧驱动模型，不套用轮式开放差速器。
- 前进 / 倒挡 / 空挡、不同挡位、持续起步、爬坡、制动 / ABS、动力切断、离地再落地以及翻滚恢复，速度、轮速、力和能量均有限且方向合理。
- 同一输入与路况在 30 / 60 / 120 Hz 下对比时间序列；设定明确的速度、距离和滑移误差阈值，并运行现有 22 车型起步 / 制动 / 碰撞 / 悬架回归。
- 安卓真机固定同一车辆、场景、帧率与画质，持续驾驶 20 分钟，比较帧时间、温升、内存与功耗；未实测前不承诺性能或发热改善。

## 独立求解器实验（2026-10-29）

新增 `utils/differentialSolver.ts` 与 `tests/differentialSolver.test.ts`。该实验接受每轮接地、载荷、摩擦系数、半径、惯量、角速度，以及每轮制动扭矩；计算轮胎纵向力、转速、滑移与开放式轴差速扭矩。AWD 前后扭矩比例可设，默认各半；对低附着轮使用有限惯性余量近似自由轮旋转与低附着限制，未建立完整引擎 / 离合器 / 差速器内部状态。输入时间步由调用方拆成不超过 1/120 秒，求解器自身不执行整车位置积分。

独立回归比较 2 秒 RWD 对称干地、左右附着不同、一个驱动轮离地、AWD 单轮离地；检查车轮摩擦上限、轮速差、左右交换、制动 / 倒车、静止与匀速滚动、零时间步、非有限输入以及 30 / 60 / 120 Hz 输入对应的固定子步一致性。上述数字仅验证合成输入下的方向和数量级，不是实车标定或安卓性能结果。

**尚未接入正式游戏：**当前手机包仍采用本文件上方的整车牵引模型。实验仅覆盖两轴四个轮，不支持三轮、多后轴、履带车辆或翻滚刚体；也没有驱动轮纵横向复合摩擦、车轮转动耗散、复杂坡地或路面形变。不能直接将其接到生产循环而声称完成。需先确定物理状态与碰撞 / 制动 / 实际载荷的耦合顺序，补多轴与全车回归，在独立构建中测量帧率，再进行安卓实驾。

### 隔离接入试验

`utils/experimentalDrivetrain.ts` 是固定 60 Hz 试验适配器，不是正式功能，限制 MINI、SEAL08、TRUCK 三辆四轮代表车。适配器先以旧模型计算基础运动及制动，另用解除原整车牵引上限的相同发动机模型计算轮端请求；用逐轮合力**替换**原先已经计入的动力，避免重复限扭和重复推力。四轮求解按 120 Hz 子步进行；制动 / ABS 暂时完全沿用旧模型，制动期间不叠加新轮胎力，轮速仅同步已有车速。

`tests/experimentalDrivetrain.test.ts` 覆盖三辆代表车的干路起步及湿干分离，比较与旧模型的速度；以相同初速比较旧制动 / ABS 逐帧速度与距离；30 / 60 / 120 Hz 下以同一固定步序运行并比对结果；其他 19 辆车拒绝进入此实验。独立差速器测试还覆盖无动力无坡度条件下接触冲量不凭空增加系统动能。

隔离接入试验的接触载荷由测试脚本提供静态值；下述开发环境桥接已使用悬架估计载荷，但还未实现真正同步耦合。忽略转弯时纵横向抓地耦合，轮胎 / 发动机 / 离合器仍是近似。三车合成数据通过不等于 22 车游戏回归、安卓可玩或热机性能达标。正式接入应先为车辆和地形建立实际采样及回退机制，支持轮胎制动力与 ABS 耦合，再通过游戏完整回归和手机实驾，保持现有游戏模式可关闭实验。


### 开发环境轮载与路面桥接

`utils/experimentalContactBridge.ts` 将上一渲染帧完成的四轮悬架接地点、`stepChassis` 估计法向载荷和接地状态转换为试验模型输入。每个轮单独采样该点地图附着力，再乘以天气和转弯牵引预算（是整车近似约束，不是完整轮胎摩擦圆）。空中轮载归零；车轮半径从当前 rig 换算，惯量 1.2 kg·m² 为临时游戏标定。四轮求解速度显示为车轮滚动角速度。上一渲染帧数据会在同帧多个固定子步复用，不等于真正同步耦合。

只能在 Vite 开发环境显式使用 `?experimentalDrive=1`，且选择 MINI、SEAL08 或 TRUCK；无参数、其他车辆及正式构建保持原动力模型。发生碰撞恢复或翻滚时暂停实验；桥接出现异常则回退旧模型。实验模式首次激活会在开发日志标注车型。

合成测试 `tests/experimentalContactBridge.test.ts` 核查开关、逐轮材料 / 轮载、转弯预算、离地及异常；`tests/experimentalDrivetrain.test.ts` 包含渲染帧率为 30 / 60 / 120 Hz 下的实际固定步累加器。Chrome 开发预览中后驱皮卡在泥泞地图轻油门由 0 到 7 km/h，刹车回到 0，日志显示实验已激活、没有实验回退。并行修改文件导致过一次 Vite HMR 重载失败，更新后恢复；这不是手机实驾或全面稳定性证明。

使用临时目录执行生产构建成功，构建产物未包含 `experimentalDrive` 激活代码；没有修改当前手机安装包。仍需实际碰撞 / 翻滚 / 湿干跨界 / 爬坡、气温、设备性能和三种车型全驾驶条件回归，且制动仍是旧模型。高性能真实物理、全车型覆盖和商业级仿真均尚未证明。
